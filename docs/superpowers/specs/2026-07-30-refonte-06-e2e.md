## Correctifs

### 1. La copie divergente qui a perdu le blocage des tuiles OpenStreetMap

`ouvrirUnTrajetVierge` (`editeur.spec.ts:4-10`) reproduit `aides.ts:18-24` **sans**
le `page.route('https://tile.openstreetmap.org/**', abort)` de `aides.ts:17`. Or
l'éditeur initialise Leaflet dès son premier rendu
(`EditeurTrajetScreen` → `LeafletCarteDesPoints.afficher` → `creerCoucheOsm`,
`coucheOsm.ts:5`), sur tous les viewports. Les cinq tests du fichier passent par
cette aide, sur cinq projets Playwright : **vingt-cinq exécutions qui sollicitent
les serveurs OSM**, alors que le projet soigne par ailleurs cette politique
(`vite.config.ts:37-40`).

Les tuiles absentes ne font pas échouer les assertions (Leaflet affiche du gris) :
le coût est la lenteur, la dépendance à un service externe et le manquement à la
politique OSMF.

Extraire dans `aides.ts` le préambule commun — `preparerLApplication(page)` qui
coupe les tuiles **puis** fait `goto('./')` — et recomposer :
`ouvrirUnTrajetVierge` et `ouvrirUnTrajetAvecUnePage` s'appuient dessus.
`editeur.spec.ts` importe l'aide au lieu de la recopier.

### 2. Six arrangements recopiés alors que l'aide existe

`points.spec.ts:35-40, 58-63, 81-86, 103-108, 124-129, 145-150` reproduisent à
l'identique les trois étapes de `ajouterUnPoint` (`aides.ts:110-120`), déjà
utilisée par `carte-editeur`, `gps`, `import-export` et `suivi`.

Les remplacer par `await ajouterUnPoint(page, …)`. **Garder les étapes
explicites** dans le seul test qui vérifie ce parcours (`points.spec.ts:12-22`) :
là, la répétition est le sujet du test.

### 3. Le scénario manquant : la sortie de simulation

Aucun scénario ne couvre `quitterLaSimulation`, ce qui a laissé passer le bug
corrigé par le lot 05 (A3). Ajouter :

- Étant donné une position simulée en fin de trajet, quand je quitte la
  simulation, que je fais défiler à la main puis que j'appuie sur « Reprendre le
  suivi », alors la page **ne se recale pas** sur la position simulée abandonnée.

### 4. Les tests ne doivent plus réimplémenter le domaine

`defilementAttendu` (`aides.ts:122-137`) recopie le calcul de
`calculerDefilement` — `0.75 * window.innerHeight`, le bornage — et
`choisirUneCoordonneePourUnPoint` (`:98`) recopie le seuil `900`. Un test qui
répète la règle qu'il vérifie ne vérifie rien.

Lire ces deux valeurs depuis la source unique que le lot 05 a mise en place
(propriété CSS personnalisée pour les trois quarts, point de rupture exposé par
le CSS) au lieu de les redéclarer.

### 5. Réparer ce que le lot 05 a signalé

Le rapport du lot 05 liste les scénarios cassés par la refonte (noms accessibles,
libellés d'état venus désormais de `presentation.ts`, superposition de la carte
qui n'est plus un `.ecran`). Les réparer **sans affaiblir les assertions** : un
test qui ne vérifie plus rien est pire que le bug.
